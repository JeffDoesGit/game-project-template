# Roadmap — {{GAME_NAME}}

Subordinate to `CLAUDE.md` and `GDD.md`. Binding process for every implementation session.

## 1. Session protocol

1.1 **Load.** Read `CLAUDE.md`, `GDD.md`, this file's §2 and §3, and `ENGINE.md`. From the repository, fresh.
1.2 **Restate STATUS.** Print §2 as it stands before doing anything.
1.3 **Pick.** The first `todo` row in §3 whose deps are all `done`, unless told to take another. A `blocked` row is not researched ahead.
1.4 **SPEC and stop.** Before touching any file:

```
SPEC <id> — <title>
What:        two sentences
GDD:         rule numbers implemented; all must be DECIDED (or the row is a PROVISIONAL placeholder and says so)
Files:       create / modify, by path
Assumptions: anything not in the GDD, stated so it can be corrected
Not doing:   what a reader might expect that is out of scope
Done when:   the observable result
Test plan:   what will be run, and what will not
Branch:      <type>/<kebab-name>
```

Wait for "go". If the reply changes the spec, reprint it.
1.5 **Work.** Files per the SPEC, nothing else. A defect found elsewhere becomes a backlog row (CLAUDE.md 4.6).
1.6 **Report.** What changed, in two or three sentences. What was tested and what was not. Then wait for "push", "PR", or "merge" — each is a separate instruction.
1.7 **Close.** Row status updated, STATUS rewritten, devlog and systems page per CLAUDE.md 4.8, all in the same PR.
1.8 **Handoff.** When the session ends mid-item, STATUS says exactly where: branch, uncommitted files, next step.
